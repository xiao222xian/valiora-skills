# 踩过的坑

| 现象 | 根因 | 做法 |
| --- | --- | --- |
| 字体偶发回退、文字宽度跳动 | FontFace 未注册完就渲染；位图缓存在字体就绪前生成 | 先 add 再 load；`fontsReady` 之后才缓存栅格；加载失败直接 `cancelRender` |
| 某个字显示成系统字体 | 子集里缺字（例：宋体黑体字重没有「昇」） | `tools/fonts.py subset` 缺字即失败；换同族其他字重 |
| 代码注释里的生僻字让子集失败 | 子集扫描 src 全部字符 | 注释避免生僻字，或改写成拼音/描述 |
| 年份计数与大字不一致 | 计数在整章里线性插值 | 章内 `yearKeys` 分段，事件期间停住 |
| 计数出现「约前 9990」 | 默认关键帧的章末哨兵 10000 被当成帧号 | `yearAt` 把 ≥10000 映射到章节时长 |
| 竖版文字压到 HUD 或被平台 UI 遮挡 | 横版布局直接缩放 | 共享布局常量的舞台带；HUD 标尺放 H−300 |
| 缩放总览的原点跑到画面边缘 | `transformOrigin` 设在目标字形上但没平移 | 加 `translate(panX)`，`panX` 随缩放进度插值到 0 |
| 并行起多条 `npx remotion still\|render src/index.ts`：很慢，webpack 缓存报 `ENOENT … rename …0.pack_` | 每条命令都从入口文件重新打包，多个进程同时写同一缓存目录 | 用 `tools/stills.sh`：先 `npx remotion bundle src/index.ts --out-dir ../build` 打包一次，再从 `../build` 并行跑 `remotion still`；改了源码再重新打包（2026-10-11 实测：同样 9 条 still，逐条打包约 100 秒、先打包约 15 秒，两轮都停在同一处字体错误；修好字体后先打包的一轮约 16 秒出齐 9 张）。脚本逐个等待子进程，任一张失败即非零退出，并先删掉同名旧图 |
| zsh 循环里 `set -- $spec` 不拆参数 | zsh 默认不做变量分词 | 循环脚本用 `bash -c` |
| shell heredoc 吃掉一层反斜杠 | 未加引号的 heredoc 会转义 | 内嵌 JS 时用 `<<'EOF'` |
| 成片元数据带「Made with Remotion」 | 渲染器强制写入 comment | 交付时 `-map_metadata -1` 重封装，只写片名与出品方并回读 |
| 整片一次渲染（约 5400 帧）总在片尾崩溃：V8 `Fatal error in ../../v8/src/objects/js-objects.cc, line 3350` / `Debug check failed: TrustedCast`，Remotion 报 `Page crashed!`；并发 8 和 4 都复现 | 同一个浏览器连续渲染数千帧后 Chrome 触发内部致命检查；同样的帧分块单独渲染全部正常 | `deliver.sh` 按章节边界分块（`tools/chunks.mjs`，每块 ≤ `CHUNK_FRAMES`，片尾单独一块），每块新起一次 `npx remotion render --muted`；concat demuxer `-c copy` 拼接；配乐母带 WAV 只编码一次（AAC 320k，bitexact），按视频时长截断；`SKIP_RENDER=1` 复用已有母版 |
| 清掉容器元数据后文件里仍有工具名 | 封装器写 `encoder=Lavf…`；x264 把版本串写进 SEI | 重封装加 `-bsf:v filter_units=remove_types=6 -fflags +bitexact -flags:v +bitexact -flags:a +bitexact`，元数据只留 title 与 artist |
| 竖版重编码后仍带 `Lavc… libx264` | 编码那一遍直接写出的文件，样本描述（stsd compressorname）记着编码器名，CLEAN 参数去不掉 | 先编码到临时文件，再流复制重封装（`-map_metadata -1` + 片名与出品方 + CLEAN） |
| 音轨里有 `Lavc…` | ffmpeg 自带 AAC 编码器把版本串写进码流 | 编码 AAC 时就加 `-flags:a +bitexact -fflags +bitexact`；事后重封装去不掉 |
| 工具名门禁误报 | 大小写不敏感的 4 字节匹配（如 `lavf`）会在压缩数据里偶然出现 | 只用长且区分大小写的签名：`grep -a -E "x264 - core\|libx264\|Lavf[0-9]\|Lavc[0-9]\|Lavc libx\|[Rr]emotion"` |
| 渲染被 `delayRender` 取消，`FontFace.load()` 报 `NetworkError` | 苹果 `/System/Library/Fonts/Courier.ttc` 没有 OS/2 表，Chrome 的 OpenType Sanitizer 拒收 | Courier 改用 `Supplemental/Courier New.ttf`；`fonts.py extract` 先查 OS/2，`subset` 后用 OTS 逐个校验（`ots` 模块或 `uv run --with opentype-sanitizer`），任一被拒即失败 |
| 竖版里的 16:9 缩略图按竖版排版（片尾已不做回顾，用户要缩略图总览时才会遇到） | 场景从 `useVideoConfig()` 取画幅，冻结后的缩略图仍拿到 1080×1920 | 用 `LayoutOverride.Provider value={{W: 1920, H: 1080}}` 包住 `<Freeze><Scene/></Freeze>`；场景尺寸一律从 `useLayout()` 取 |
| 印章读成别的字（「生」「中」「神」） | 篆书字形与章法不熟悉 | 先给 1–2 版让用户挑；小尺寸（28px）与缩略图链路都要检查字腔不糊 |
| 封面色带与片中光谱不一致（没有 AI 底图、封面退回章节色谱时） | 改片中光谱时忘了封面 | `src/Cover.tsx` 的色谱直接读 `timeline.ts` 的章节配色，不另抄一份；AI 底图的强调色也取自片中配色 |
| 缩略图停在动画中途（片尾已不做回顾，用户要缩略图总览时才会遇到） | 冻结帧取在计数或生长中途 | 缩略图帧取每章动画完成后的帧 |
| 多轮自动评审拖慢交付 | 评审-修改循环跑到第三轮 | 关键创意给用户 1–2 版挑；评审最多一轮，之后人工判断 |
| 配乐时长不够 | 经 OpenRouter 调用的 Lyria 3 Pro 单条最长约 3 分钟（实测 177–181 秒） | 片长按 3 分钟以内规划，或分段生成再接；单价以调用时为准（2026-10-11 为 0.08 美元一条） |
