# 事实台账与示意说明

## 台账

每一条将上屏的事实写一行：原文、所在章与帧、类型（年份 / 数字 / 引文 / 地名 / 人物 / 归属）、
来源（典籍篇章或机构页面）、结论、改写。来源优先：原典 > 权威机构（博物馆、政府、学术机构）>
通行年表与教材 > 百科（只作线索）。

旁白与字幕（中英）说出的事实同样以台账为准：旁白稿只用台账里成立或已改写的条目，英文字幕里的专名与台账、片中原文一致。

片内算法实跑得出的数字和指向性标注（「答案在这一块」）也进台账：写明是实测值还是理论值、
由哪次运行得出；画面结构改动后复查每一条指向。

屏幕上的计数按观众在画面上能数到的口径算：「165 块 / 剪掉 69 块」里含 82 个已被切开、画面上已不存在的父块，
观众会算出剩 96 块，实际只剩 14 块（2026-10-11 终审，改为显示画面上现有的块数）。空数组、未定义值的默认值
不能当数据上屏（最后一代没有试验，「步长 0.00」只是默认值）。数值格式要防「-0.0」，负号用「−」，与片中公式一致。

## 对抗核查

- 能用多 Agent 时，每条事实由独立核查者先写出「应该是什么」，再看片中写法，默认试图驳倒。
- 不成立：改写或删除；部分成立：按核查建议改写；成立：保留出处。
- 改动后的新文案再核一遍：新文案不能引入台账之外的新事实。

## 选样与未单列

懂行的观众第一句常常是「为什么没有 X」。2026-10-11《跳出局部最优》发布后，观众问「为啥没有包含梯度下降相关的算法」：
结构方案里写了不单列的理由（它是局部方法，作片头的反面，就是那颗滚进浅谷的球），但片头没标名，
片尾说明只列了核查者提到的「多起点、DIRECT」，观众看不出这是有意安排。

- 结构方案阶段列一张「缺席名单」：同领域最有名、最常被教的成员里，没有成章的每一个，各写一句理由。
  以无名形象出现在片中的（片头的反面、某章的对照组）也算缺席。
- 名单上每一项都要在画面上交代：全部项目都写进片尾选样说明，名字和理由都写（例：「梯度下降是局部方法，
  作片头的反面；多起点、DIRECT 未单列」）；以无名形象出场的，另在出场处就近标名（例：片头的球标「梯度下降 · 示意」）。
  只写在结构方案或交付报告里不算交代。
- 对抗核查时单独问一句「懂行的观众会说缺了谁」，把答案和缺席名单对一遍，补漏后再定稿片尾说明。

## 本片型常见坑

| 坑 | 正确做法 |
| --- | --- |
| 年份计数在画面停在某事件时继续跑，读出与大字不一致的年份 | 用章内 `yearKeys` 分段，事件期间停住 |
| 插值取整得到「前 0」 | 历史纪年没有 0 年：负数至少显示「前 1」，正数至少「1」 |
| 计数动画中途被截成缩略图（如 4,490 而非 4,500） | 缩略图取计数完成后的帧 |
| 时间轴各段按片中时长分，观众以为是年数比例 | 片尾写明「底部标尺各段长短不按年份比例」 |
| 合并时期（夏商西周、三国两晋南北朝）称「时代」 | HUD 与片尾说明称「章」，片头可称「时代」 |
| 古文字与今字并列，观众把示意字形当真 | 标「字形示意」；与主体不同的字单独说明（例：「甲骨一格为『人』字」） |
| 简体字出现在不存在它的时代（例：小篆里没有简体「汉」） | 该格改用当时字形（小篆「漢」），并说明 |
| 地图画出疆域线 | 只画经纬网与点位，标「路线与地名为示意」 |
| 引文凭记忆写 | 逐字对原典；改动过的不加引号 |
| 方法、发明类编年的年份口径前后不一（2026-10-11《跳出局部最优》：方案定了「按首次公开发表计」，差分进化取 1995 年报告，「没有免费的午餐」却写 1997 年期刊；蚁群写成 1992 年博士论文，Dorigo 自标 1991） | 结构方案里写定一条年份口径（例：首次公开发表，技术报告、会议论文都算），核查时逐条对照；为观众熟悉而改取标志性论文的，在片尾说明里点名（例：「年份取各方法首次公开或标志性论文；没有免费的午餐定理 1995 年先以技术报告发布」）。年份改了，要复查章节顺序、相邻章的轴范围和 `axisKeys` |
| 格式固定的行暗含说法：各章都是「年份 · 提出者」，唯独第 1 章「1957 · Richard Bellman」，观众会读成他提出了穷举（他提出的是「维度灾难」这个说法）；NASA 卫星天线用的是进化算法，却出现在遗传算法一章（2026-10-11《跳出局部最优》核查与终审） | 同一格式的行全片含义一致；行上的人不是本章方法的提出者时，在同一行写明他做了什么（「1957 · Richard Bellman：『维度灾难』」）；不写「首创」「首次提出」「命名」，除非核到原始出处；章内案例属于上位概念的，用上位词（写「进化算法」，不写「遗传算法」） |

## 示意说明的写法

- 就近标注：「马家窑类型旋涡纹 · 示意」「路线与地名为示意」「中轴线建筑为示意」。
- 片尾总说明：通行年表或年份口径（及破例）、示意范围（地图、建筑、器物、纹样、古文字）、字体只代表风格、
  标尺不按年份比例、选样依据与未单列名单（名字加一句理由）。
- 不写制作方式；AI 生成内容在交付报告里逐项列清单，平台上标不标由用户决定（见下文「AI 生成内容清单」）。

## 片尾署名

片子要能脱离简介独立成立：观众只看到视频，也能找到每份需要署名的素材的作者和许可。

- 片尾署名卡逐条写需要署名的素材（CC BY 照片、影像、三维模型、音效）：「作者 · 标题 · 许可」，按片中出现顺序，每份一次。
- 用到的每种许可写成「许可名 + 短链接」：`CC BY 2.0 creativecommons.org/licenses/by/2.0`、`CC BY 4.0 creativecommons.org/licenses/by/4.0`；
  改动过的素材写一句（「以上素材均经调色、裁切」）。CC0、公有领域、Pexels 不要求署名，可另起一行致谢。
- 不写「许可链接见视频简介」这类指向片外的话。2026-10-12《如何打造一款特斯拉》片尾署名卡写了这句，用户在视频号把简介
  改写成自己的话、没有署名段，片子指向了不存在的链接；B 站、YouTube 也只能靠追加署名段补救。
- 简介里的署名段是补充，给出逐条的来源链接；完整版与压缩版的写法、长度见 [publish-handoff.md](publish-handoff.md)。
- 起步模板：素材表是 `src/credits.ts` 的 `CREDITS`（`{author, title, license, url, changed}`，空数组时片尾不显示署名块）与 `CREDITS_CHANGED`；
  `src/scenes/S14Outro.tsx` 读它排片尾，`tools/credits.mjs` 读它写简介的完整版与压缩版，两边不会对不上。许可短链接由 `licenseUrl()`
  从许可名推出，不要求署名的素材由 `otherLine()` 合成一行；字号随条目数在留白内自动缩小（16:9 最小 14 px）。缩到最小仍放不下时，改成单独一张署名卡，不删条目；改过片尾说明后看一眼片尾静帧。

## AI 生成内容清单

交付报告和发布交接单都列一张清单，逐项写出片中每个由生成模型做出的元素，发布时由用户据此决定平台上怎么标。

| 元素 | 类型 | 服务商 | 模型 / 音色 | 用在 |
| --- | --- | --- | --- | --- |
| 旁白 | 语音合成（TTS） | 例：豆包语音 | 例：Seed-TTS 2.0，音色 `zh_male_ruyayichen_uranus_bigtts` | 片头与 01–13 章；用户录音替换的句子单列 |
| 配乐 | AI 音乐 | 例：OpenRouter | 例：Lyria 3 Pro（整片）、Lyria 3 Clip `google/lyria-3-clip-preview`（分章） | 写明哪几章 |
| 封面底图 | AI 图像 | 例：OpenRouter | 例：`openai/gpt-5.4-image-2` | 写明哪几个比例 |
| 片中画面、影像、音效 | 按实际 | | | 没有就写「无」 |

- 每一类都要有一行：没有的写「无」（例：「片中没有 AI 生成画面」），不写「部分 AI 辅助」这类含糊说法。三维渲染、程序动画、
  排版不是生成模型做的，不进清单，也不反过来写「全部手工」。
- 平台事实（2026-10-12 核实）：
  - YouTube 帮助（support.google.com/youtube/answer/14328491）把 AI 生成的音乐
    列为需要声明的情形；缩略图、完全动画的内容不需要声明；非写实内容选了声明后，标签只出现在展开的简介里。
  - 《人工智能生成合成内容标识办法》（2025-09-01 施行）第十条：用户发布生成合成内容时，「应当主动声明并使用服务提供者提供的标识功能进行标识」。
    TTS 旁白、AI 配乐、AI 封面底图都是生成模型产出的音频或图片。
  - 作者的长期偏好（2026-10-01）：视频号、B 站、小红书的 AI 标注默认不勾，当次另有要求再勾；这条偏好不涉及 YouTube。
- Skill 不替用户做这个决定：不自动勾选或取消 AI 标注，不在报告、交接单或简介里写「已合规」「无需标注」之类结论，
  也不把偏好当成合规依据。交付报告摆出清单和上面的平台事实，交接单「发布时需要你决定」里逐平台列一项。
- 谁问、什么时候问，取决于 `lov-media-publisher` 的 Profile `skills.lov-media-publisher.records.auto_publish`（2026-10-12 核对）：
  登记为 `confirm-final` 的平台在终稿确认里写明「含生成素材，按偏好未标注」，由用户当次决定；登记为 `auto` 的平台按上面的偏好
  不标注、直接提交，发布后的报告里才写明，提交前没有人再问（2026-10-12 作者把 B 站、小红书设为 `auto`，视频号仍是 `confirm-final`）。
  所以交给发布时，在交接回复里直接贴出 AI 生成内容清单，并写明 B 站「创作声明」投稿后不能改；`auto` 平台要标注，需要用户在这次
  发布请求里说出来。本 Skill 不改这个默认，也不强制标注。2026-10-12《如何打造一款特斯拉》的 B 站选了「含AI生成内容」，是用户当次确认的。
- 片内仍不写制作方式（硬门禁）；AI 声明只走平台的标识功能和用户自己写的简介。
