# 活动策划师 · Event Planner

把一份嘉宾材料（履历 / 公众号简介 / 领英 / 公司官网介绍）转成**一份可直接交付主持人和运营的活动策划案**：主题与宣传文案、分钟级 rundown、分层主持问题清单、伴手礼与宝藏功课。

核心价值在"从嘉宾履历里**挖到别人看不到的角度**"，而不是套模板。下面的方法论是这个 skill 的 IP，**严格按步骤执行，不要跳步、不要用你自己的通用知识替代。**

## When to Use

- 用户粘贴 / 上传嘉宾材料，要出一份对谈 / 分享 / 沙龙 / 工作坊的策划
- 用户已经订了嘉宾，需要快速出主持手卡和宣传文案
- 用户在筹备活动，需要判断怎么策划最匹配这位嘉宾的"稀缺性"

## Workflow (MANDATORY)

### Step 1: 获取嘉宾材料

**有文档时：** 读取用户提供的材料。优先级：
1. 结构化履历（CV / LinkedIn 导出 / 公司 /about 页）
2. 长文本自述（公众号头条、播客 show notes、访谈文字稿）
3. 作品/产品链接（GitHub、个人站、代表作）

如果是 .docx / .pdf，先转 markdown：

    pandoc --wrap=none input.docx -o /tmp/guest.md

**没材料时：** 通过对话收集以下最少信息，**不要硬编**：
- 嘉宾姓名 / 身份标签（一句话）
- 一个代表性作品 / 项目 / 事件
- 一句他"不常被问到但其实很想聊"的话题（如果用户不知道，就省掉这条，后面第 3 步我们从履历挖）

### Step 2: 活动参数澱清 (MANDATORY `AskUserQuestion`)

**必须用 `AskUserQuestion` 收集参数，不要假设。** 一次问完，不要串行追问：

```
开始策划这场活动！先确认几个关键参数 👇

━━━ 🎭 活动形态 ━━━
 a) 对谈 / 访谈 (1v1 或 1vN)  — 主持人 + 嘉宾
 b) 主题分享 / 技术分享        — 嘉宾单人演讲 + Q&A
 c) 沙龙 / 读书会               — 多人圆桌，关系型
 d) 工作坊                      — 动手共创

━━━ 👥 观众画像 ━━━
 1) 垂直专业人群（同行）
 2) 跨界泛科技 / 创作者
 3) 目标客户 / 投资人
 4) 兴趣社群 / 朋友圈

━━━ ⏱️ 总时长 ━━━
 默认 90 分钟（含入场+Q&A+合影）。需要的话告诉我实际时长。

━━━ 🎨 气质基调 ━━━
 i)   学术深度型   — 硬核、节奏慢、留白多
 ii)  媒体锐度型   — 金句密集、冲突感、好传播
 iii) 社群温度型   — 轻松、互动多、有记忆点
 iv)  商务转化型   — 明确信任曲线、引导到下一步

━━━ 📍 场地 / 渠道 ━━━
 线下城市？线上平台？混合？

示例回复："对谈, 跨界泛科技, 120分钟, 媒体锐度, 上海线下"
```

### Mapping — 参数如何进入生成

| 参数组合 | 对文案 / rundown / 问题的影响 |
|---|---|
| 对谈 + 媒体锐度型 | 问题要有交锋感；rundown 留 40% 自由对话；标题用反差句 |
| 主题分享 + 垂直专业 | 标题用 know-how 关键词；问题少而深；rundown 切 3 段 + 长 Q&A |
| 沙龙 + 社群温度 | 标题用"邀请体"；rundown 做"破冰→关键词卡→自由交流"结构 |
| 工作坊 + 跨界 | 标题"共创/上手"；rundown 60% 动手 + 30% 点评 + 10% 展示 |
| 商务转化型 | 收尾必须有"下一步" CTA；伴手礼绑定 lead magnet |

### Step 3: 挖掘嘉宾"稀缺角度" (IP 核心，不要省)

读完嘉宾材料后，按下面这张表逐格填写。**这一步不对用户展示原始表格**，但你必须在内部把每一格都想清楚，否则后续输出会流于"通用简介"。

| 维度 | 要找什么 | 怎么挖 |
|---|---|---|
| **身份张力** | 同一个人身上两个看似冲突的身份 | 职业 vs 爱好、学历 vs 实践、主业 vs 副业 |
| **时间锚点** | 3-5 年内一次"转折 / 顿悟 / 赌一把" | 离职、转行、重大项目、公开失败 |
| **反共识观点** | 他同行里属于少数派的判断 | 公开文章里"我认为/我不同意"的句子 |
| **私人偏执** | 他在某件小事上异常较真 | 审美、工具、流程、措辞 |
| **尚未被问过的问题** | 别的访谈都在问 A，但他材料里最重的是 B | 对照公开访谈记录 vs 自述重心 |
| **代表性作品背后的故事** | 作品介绍之外的制作史、遗憾、彩蛋 | GitHub commit 史、产品更新日志、自己写的复盘 |

如果材料薄，不要编。在"主持人问题"章节标注"→ 需活动前和嘉宾确认"。

### Step 4: 生成策划案 Markdown

按以下结构一次性生成完整文档。**所有内容必须来自 Step 1 的材料或 Step 3 的挖掘，禁止通用化套话（"在这个 AI 时代" 这种句子一律删掉）。**

```
# {嘉宾名} × {活动主题} 策划案

| 活动形态 | {Step 2} |
| 时长     | {Step 2} |
| 目标观众 | {Step 2} |
| 气质基调 | {Step 2} |
| 策划日期 | {YYYY-MM-DD} |
| 版本     | v0.1 |

## 一、嘉宾速览

### 1.1 一句话介绍
  — ≤ 30 字，金句式，必须带至少一个具体作品/数字/事件

### 1.2 核心标签（3 个）
  — 每个标签是"名词 + 反差修饰"，如"做硬件的诗人" 而不是"跨界创作者"

### 1.3 稀缺角度（内部版，策划参考）
  — 把 Step 3 表里最有冲击力的 2-3 条摘出来，给主持人看

---

## 二、主题与宣传文案

### 2.1 活动主标题（3 选 1）
  方案 A — {句式：悬念型} — 适合{渠道}
  方案 B — {句式：反差型} — 适合{渠道}
  方案 C — {句式：人格型} — 适合{渠道}

  每个方案下面附 1 句创作说明（这个标题在钩什么情绪）

### 2.2 副标题 / 引导语 (一句)

### 2.3 Teaser 文案（3 个版本）
  - 朋友圈版（≤ 80 字，带一个钩子句）
  - 公众号预告版（150-250 字，含嘉宾一句原话 + 3 个本场将讨论的问题）
  - 长文案版（400-600 字，完整开场白）

### 2.4 海报关键信息（给设计师用）
  - Hero 关键词（≤ 6 字）
  - 副关键词 × 3
  - 推荐配色情绪词（暖/冷/对比强/学术）

---

## 三、Rundown (分钟级流程表)

表格形式。列：起止时间 | 环节 | 主持人动作 | 嘉宾动作 | 备注

**时间分配原则（按活动形态调整）：**
- 对谈：开场 10% + 嘉宾自我介绍 5% + 核心对谈 55% + Q&A 20% + 收尾合影 10%
- 主题分享：开场 10% + 分享 55% + Q&A 25% + 收尾 10%
- 沙龙：破冰 15% + 关键词环节 20% + 圆桌交流 50% + 总结 15%
- 工作坊：暖场 10% + 任务讲解 15% + 动手 50% + 展示点评 20% + 收尾 5%

每个环节必须写"主持人的一句串词"，不能只写环节名。

---

## 四、主持人问题卡（分层）

总量 **8-12 个**，按下面四层分布：

| 层 | 数量 | 功能 | 问题特征 |
|---|---|---|---|
| L1 · 破冰 | 1-2 | 降低心理门槛 | 人人能答、短、带点幽默 |
| L2 · 事实 | 2-3 | 建立履历锚点 | "你当时为什么..." |
| L3 · 观点 | 3-4 | 引出稀缺角度（Step 3 的料） | "你公开说过...，这背后的判断是..." |
| L4 · 未来/留白 | 2-3 | 情绪收尾 | "如果...", "你最近偷偷在..." |

**写作要求：**
- 每个问题 ≤ 40 字
- 不要"你怎么看 XX" 这种空壳问题
- L3 的问题必须绑定一条 Step 3 挖出来的具体材料（引用出处）
- 每个问题后附：**"预期回答方向 × 追问钩子"** (给主持人应变用)

示例格式：
```
Q3 [L3·观点] 你 2023 年在公众号里写"我不相信 AI Native"，一年后你创业做了 AI 产品。中间发生了什么让你改主意？
   预期方向：从"怀疑技术炒作"到"看到某个具体场景 click"的心路
   追问钩子：那个 click 的具体瞬间能描述一下吗？是在看什么？
```

## 五、伴手礼 / 宝藏功课

### 5.1 伴手礼建议（2-3 个方案）
  从嘉宾"私人偏执"维度（Step 3）反推礼物，**不要送通用周边**。
  每个方案写：物品 | 为什么与嘉宾气质合 | 预算区间

### 5.2 活动后的延伸（宝藏功课）
  列 3-5 个观众可以做的事：读哪本书、follow 哪个账号、访问哪个 repo、
  做一次怎样的练习。每条附一句"为什么这对理解嘉宾重要"。

### 5.3 记忆点小道具（可选）
  如果气质基调是"社群温度型"或"媒体锐度型"，建议 1 个现场小道具
  （例：关键词卡、可签名的实体物、定制标语贴纸）。
```

### 内容生成规则（重要）

1. **履历锚定**：每个观点、每个问题、每条文案都要能追溯到嘉宾材料的具体一句话或一个事实。无锚点的内容删掉。
2. **数字优先**：说"多年经验"不如说"做了 11 年"。说"大项目"不如说"3000 万用户"。
3. **拒绝套话清单**（生成后自查并删除）：
   - "在这个 AI 时代"
   - "一场不容错过的"
   - "思想的碰撞"
   - "跨界融合"（除非嘉宾自己这么定位）
   - "大咖"、"大佬"、"大神"
4. **中文场景**：所有文案默认简体中文。嘉宾名、产品名、专有名词保持原样不翻译。
5. **长度控制**：整个策划案 markdown 控制在 1500-2500 字。冗长是 AI 气味。

### 文件命名

按品牌方命名规范：

    品牌方-{嘉宾名}-{活动主题slug}-{YYYY-MM-DD}-v0.1.md

示例：`品牌方-张三-ai-独立开发者对谈-2026-05-18-v0.1.md`

输出到 `./output/articles/` 目录（用户若未指定）。

### Step 5: 交付确认

输出给用户：
- 策划案 markdown 路径
- 一个摘要（3 条）：本场最大的稀缺角度是什么 / 最关键的一个主持问题是什么 / 最需要提前和嘉宾确认的一件事是什么
- 建议的下一步（2 选 1）：
  - 需要海报？`/lov-event-poster {md_path}`
  - 需要 PDF 交付？`/lov-any2pdf {md_path}`

### Step 6: 迭代

如果用户说"太通用" / "不够尖锐" / "文案没钩子"：
- 回到 Step 3，检查是否跳过了挖掘
- 重点回看 L3 问题是否每个都绑定了具体材料
- 如果材料实在薄，主动问用户："要不要我列 3 个在活动前需要和嘉宾对齐的关键问题？"

不要一上来就"让我重新生成一份"——先定位问题层。

## Runtime context (shared)

运行前读取本 Skill 包的 `skill.yaml`，由宿主提供 `skill-runtime/v1` 上下文。字段解析顺序为：当前请求、项目上下文、个人 Preferences、品牌 Profile、通用默认值。

- 只使用 Manifest 声明的字段；Profile 保存公开品牌事实，Preferences 保存个人工作偏好。
- `required: true` 字段缺失时，按 Manifest 的问题配置向用户提出一个聚焦问题；用户明确同意后再保存回答。
- 报错提供可复制的 `context_id`、字段路径与来源，诊断内容避开秘密、完整私人路径和原始配置。

## 通用反馈闭环

用户在 Skill 驱动任务中提出修改意见时，继续当前产物前必须执行：

1. 先判断意见是 `task-specific`（仅本次）还是 `reusable`（可跨任务复用）。
2. `task-specific` 只修改当前任务，不改 Skill。
3. `reusable` 先确定作用域：领域规则先更新对应 canonical Skill；适用于所有 Skill 的规则先更新共享规范。
4. 完成规则更新、版本、lint 与分发核验后，再把修改应用到当前任务。
5. `reusable` 修改会使此前的“确认”“继续”“发吧”失效；完成当前产物修改和回读后必须停下，等待用户下一步指示，不自动进入发布、提交或其他外部写入。
