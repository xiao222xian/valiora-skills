# 上下文来源：聊天记录、自述、公众号与现场照片

采访录像只说了被访者当场说的话。片子里的身份、账号、活动数据和人物关系，常常要从这几类来源补齐。每条进片的事实都写进
`work/facts.md`，带出处与用途（字幕 / 人名条 / 讲解图形 / 简介 / 只作背景）。

## 微信聊天记录（`lov-wdb-cli`）

- 作者说「看聊天记录『某某』」时，用 `lov-wdb-cli` 只读查询：先 `contacts --match 名字` 确认联系人（备注、昵称、签名），再
  `chats --from 日期 --to 日期 --contact 备注 --format jsonl` 导出到 `work/context/`。不直接打开微信原库；不把密钥、完整聊天正文写进日志或交付报告。
- 先找授权信号：被访者有没有要求保密、不露脸、不发布（见 style-grammar「主体与立场」）。有就先停下交作者确认。
- 能取的通常是：被访者自己报的小红书 / 视频号 / 公众号账号（作者希望观众去 @ 的那个）、群聊与名片、对方发来的现场照片或文章链接。
- 聊天里对方转发的账号名、链接只作为线索：上屏前和采访原声或公开页面对一遍（观测实例：聊天里「可以@好奇爆爆爆」与采访中
  「我的小红书叫好奇爆爆爆」一致，才写进人名条之外的结尾字幕与简介）。
- 谁发的看 `senderUsername`（作者本人的 wxid 就是作者发的）。lov-wdb-cli 0.6.4 及更早读微信 4.x 时 `isOwn` 恒为空：它按方向列判断，
  4.x 的 `Msg_*` 表没有方向列。`isOwn` 为空只表示判断不了，不等于对方发的。
- 作者从聊天里另存的图片名为 `Weixin Image_<发送时间>_<序号>_….jpg`，序号就是那条消息的 local_id（lov-wdb-cli 输出的 `source.rowid`）：
  素材夹里的图按它对回聊天，就知道是谁发的、前后说了什么。观测实例：对话易七猫素材夹的 `Weixin Image_20261029222111_405_5168.jpg`
  是 2026-10-29 22:21:11 的第 405 条消息（易七猫发来的产品照）；易七猫引用第 421 条说「这张可以删」，`生活照/` 里正好没有 `_421_`。

## 被访者本人的公开文字（朋友圈、公众号、活动复盘）

- 作者转贴的被访者自述原样存进 `work/context/<name>-statement.md`，在文件里列出可核实的事实（日期、人数、合伙人、承诺）。
- 自述是事实来源与叙事参考，不是文案来源：字幕只用采访原声；自述里的感悟句、致歉句不做成字卡。需要引用时用画面引述
  （截图或引号 + 出处），并先问作者是否合适。
- 自述与采访说法不一致（人数、日期、头衔）时两边都不改，在交付报告里逐条列出，由作者决定。
- 宣传口径（「首创」「首场」「最大」）保留为被访者的说法，不写成片子的结论；简介里也用引述。

## 公众号文章

- 作者给公众号名或文章链接时，用网页读取能力取正文（`lov-media-fetch` 或浏览器），存进 `work/context/`，只取与片子直接相关的事实：
  项目定位、活动规模、时间线、合作方、可公开的账号名。
- 公众号里的图片可以作 B-roll（活动现场、海报、产品），用前确认是被访者自己发布的、作者同意使用；片尾或简介按需要署名。
  图片里的二维码、联系方式、报名信息不上屏（打码或裁掉）。
- 不在片子里为公众号导流，除非被访者在采访里亲口这么说、作者也同意。

## 地点、机构与专名

- 两个转写模型听不一致的地名、机构名（观测实例：「茉莉营 / 魔力营」），用公开资料核实（检索官方报道），并对照视频的 GPS 元数据
  （`com.apple.quicktime.location.ISO6709`）。核实后才进地点条。
- 学校、公司、头衔这类身份信息：只写被访者亲口说过的；能否公开问作者一次。

## 现场照片

- HEIC 转 JPEG 预览后逐张看：侧拍（采访进行中）、合影、产品特写。读 EXIF / 创建时间，确认是这场采访。
- 侧拍照片里露出采访者时，最适合放在被访者点名采访者的那句（「关注 XX」）；合影放在收尾。
- 合影里的其他人（朋友、工作人员）默认可以出镜；画面里的胸牌、屏幕、二维码按 lov-media-creator delivery-contract
  「发布前隐私扫描」处理。照片同样做自然美颜。
