# 发布交接（视频号首发）

发布动作归 `lov-media-publisher`：账号核对、字段写入、终稿确认、单次提交、列表回读都按它的门禁走。本 Skill 负责交过去的东西是对的，
并把一次确认里需要作者拍板的事项收齐，免得发布页已经填好又因为字幕或事实再返工。

## 交接前

- `deliverables/platform-wechat-channels-vX.mp4`：与审片版同一份编码时用 APFS 克隆，并在报告里写明两者 SHA-256 相同；字幕交付方式 `burned-in`。
- 封面：作者选定的 3:4（A 或 B）与同一视觉的 4:3 分享卡，两张一起交；另一版 3:4 留作备用。视频号封面槽数以发布页现场读到为准
  （观测：一个 3:4 槽，有时是「个人主页卡片 3:4 + 分享卡片 4:3」两个槽），不要写死；`cover_status` 覆盖 3:4 与 4:3 两张。
  发布方只读到一个槽时，4:3 不上传，在发布记录里写明「4:3 本次未用」。
- 文案 `publish-copy-vX.md`：
  - 短标题 6–16 字、不含逗号（例：「05后在深圳造美国版麻将机」13 字）。
  - 描述用钩子型短描述：第一行片名，第二行最强的那段故事（原话压缩），空一行写被访者希望观众去关注的账号；不写系列介绍、章节摘要和客套话。
  - 话题 5–10 个，都在片中出现过：领域（创业）、人群（05后、大学生创业）、对象（AI硬件、桌游）、地点（深圳、具体园区）。
  - 视频号描述里不能 @ 其他平台账号，用文字写出账号名。
- 先跑 `check_copy.py --platform wechat-channels`（在 lov-media-publisher 里）。

## 一次确认收齐这些事

终稿确认的字段表之外，把下面几项放进同一条消息，作者一次回复即可：

1. **终稿可以发**，并同时算作批准字幕：附 SRT 文件名与 SHA-256，回复后记 `subtitle_status=approved`，另存 `subs-approved-vX.srt`。
2. **待确认事实**：两个转写模型分歧的专名（例：「关注川哥 / 关注穿着」）、身份信息（例：「北理工读大四」）、画面里露出的产品页能否出镜。
3. **合集**：列出账号现有合集；作者点名一个不存在的合集名时，由发布方新建（视频号合集名 ≤ 10 字，建后不能改名）。
4. **原创声明**：勾选要接受平台的《原创声明须知》《使用条款》，属于代作者接受条款，必须作者在对话里同意。
5. **位置**：平台常按定位自动带入（例：「深圳市」），问保留还是不显示。
6. **生成内容标注**：配乐是 AI 生成时写明「含生成素材，按偏好未标注」或按作者要求标注。

把默认方案写成按钮式的一句话（例：「终稿确认可以发，字幕和三处事实都对；合集不加；同意代勾原创条款并声明原创；位置保留」），
作者只需改其中一项。作者回「发吧」时，按这条默认方案执行，并把他改动的那一项（例：「合集使用 AI面对面」）照办。

## 发布后

- 发布方在内容列表重载后找到唯一条目，状态原文（例：「原创审核中」）记 `publish_status=platform_pending`，审核通过前不写 `published`；
  交付报告、案例记录与对外说明都写「已提交、平台审核中」，回读公开页面确认通过后才改成「已发表」。
- 记下发布页实际读到的封面槽（几个、各自比例）以及每张封面用在哪个槽。
- 新建合集要回读合集分页里的内容数。
- 把发布记录（字段表、平台改写、提交时间、列表原文）写回交付报告。视频号发表后视频本身换不了；列表卡片的「修改描述和封面」入口
  未验证能改哪些字段，不要说「发错了能改」。
- B 站横版不在首发里，派生做法与要不要先问见 [pipeline.md](pipeline.md)「13 横版派生」。

## B 站跟发

视频号是首发平台，作者只把控这一个；B 站在 lov-media-publisher Profile `records.auto_publish.bilibili=auto` 时字段回读通过后直接提交，
发完再报告（作者 2026-10-27「以后不用询问我，只需把控第一个发布平台即可」）。本 Skill 交过去的东西：

- `platform-bilibili-vX.mp4`、4:3 槽用竖版那张分享卡、16:9 槽用同一视觉的 `cover_16x9-<v>-vX.png`（B 站两个槽互相独立，列表与空间用 16:9）。
- `publish-copy-bilibili-vX.md`：从视频号已发布文案做最小适配，不重写。描述首句（钩子问句）当标题，简介同一句；视频号的 `#话题` 原样
  改成标签字段；片子没有上屏章节时简介不加时间轴。先跑 `check_copy.py --platform bilibili`。观测实例：采访 Ricky 标题 25/80 字、6 个标签。
- 视频号上一次确认收齐的事项在 B 站沿用：字幕批准、事实、生成内容标注（采访 Ricky 按作者偏好不标注，B 站创作声明选「内容无需标注」）。
- 合集：视频号的合集在 B 站不一定有同名合集。没有时不建、不进合集，发布后报告写明；要建由作者说。原创 chip、分区按发布方的 B 站规则处理。

发布后：B 站稿件先「审核中」，回读到「开放浏览」后才记 `publish_status: published`（采访 Ricky 提交后约 1 分钟开放）；BV 号、公开封面 `pic`、
标签集合与改写处写进 `delivery-report-bilibili-vX.md` 的发布记录。B 站稿件发布后还能改标题、简介、标签、封面与合集，改完要重新投稿。
横版报告不写「待你确认」清单；只有按发布方规则要停下等作者回复时（例如作者当次说要先看）才列。
