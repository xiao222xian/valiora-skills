# Typeless-style cleanup contract

本参考描述 `lov-typeless-prompt` 的语义边界与版式判定。它是公开、可审阅的行为
契约，不包含任何第三方专有 Prompt。

## Correction decisions

| 输入现象 | 处理 | 不允许 |
|---|---|---|
| “周一，不对，周二上线” | 只保留“周二上线” | 同时保留周一与周二 |
| ASR 误抄或完全无作用的重复 | 合并为一次 | 保留机械重复造成噪声 |
| 用于强调、递进或表达情绪的重复 | 保留其语气作用，必要时轻量整理 | 一律去重并弱化表达强度 |
| “嗯、那个、就是说” | 不承载信息时删除 | 删除其后真正的限定条件 |
| 明显唯一的同音或 ASR 错字 | 直接纠正 | 对不确定专名做猜测 |
| 问题、请求、命令或待办 | 整理其表达 | 回答、执行或扩展方案 |
| 数字、路径、URL、代码、版本号 | 原样精确保留 | 为顺口而改写关键 token |

## Voice fidelity contract

清理的对象是口述噪声，不是用户的个性。判断一句话是否可以删除或改写时，先问：
它是否承载事实、态度、情绪、确定程度、强调、修辞或个人节奏？只要答案为“是”，
就必须保留其作用。

优先级固定为：改口与事实准确 → 信息完整 → 声音与情绪保真 → 结构清楚 → 字数
精简。不得为了更短、更像产品文档或更“专业”，牺牲前四项。

### 必须保留

- 主观感受和自我定位，如“我感觉”“对我来说”“我还是更喜欢”。
- 表达强度和情绪的措辞，如“太狠了”“真的很割裂”“完全没有感性”。
- 有语义作用的犹豫、保留和不确定，如“可能”“有点”“我还不太确定”。
- 有辨识度的比喻、反问、对照、递进和强调重复。
- 从体验到判断的情绪递进，不把它压成一个抽象结论。

### 可以清除

- 不承载任何意义或语气的“呃”“那个”“然后然后”。
- 说到一半即被放弃、且没有留下有效限定的假启动。
- ASR 误抄造成的连续重复。
- 已被用户明确否定或替换的旧版本。

### 不允许的泛化改写

- “压缩太狠了，原汁原味的表达都丢了”不得概括成“内容精简过度”。
- “读起来完全没有感性”不得弱化成“文本风格偏理性”。
- “这个交互让我很别扭”不得替换成“该交互体验有待优化”。

默认采用轻度整理。原句已经自然时，优先保留措辞，用段落、空行和列表解决结构
问题；整理后的有效内容可以接近原文长度，不以压缩率作为质量指标。

## Layout decision matrix

1. 只有一个简单意图：一个短段落。
2. 两个及以上并列事项：项目符号，一项一行。
3. 有先后依赖：连续编号步骤。
4. 有条件、互斥方案或左右分支：项目符号加粗短标签。
5. 产品或开发反馈：先写目标，再分开当前表现、问题和期望调整。
6. 三组及以上不同主题：使用短标题；每个标题下仍遵守一项一行。

不要按字数机械决定结构。即使文本很短，只要包含现状/期望、两项要求或条件分支，
也必须分行。即使文本很长，如果只有一个连续论点，也不要制造空标题。

## Mandatory whitespace

- 不同逻辑块之间恰好留一个空行。
- 列表项各占一行；不要在一个列表项内用多个分号继续堆事项。
- 最多两层；第二层只用于解释父项下真实存在的子分支。
- 标题后直接进入正文或列表，不使用空泛导语。

## Real examples

### Node anchor feedback

输入：

> 目前是 hover 节点边缘才出现锚点，应该改成 hover 整个节点就出现锚点。锚点
> 只要左右两个，从左边拖出去创建前置节点，从右边拖出去创建后置节点。

输出：

调整节点锚点交互：

- **触发范围**：hover 整个节点时显示锚点，不再只在边缘触发。
- **锚点数量**：仅保留左右两个。
- **创建规则**：
  - 从左侧拖出：默认创建前置节点。
  - 从右侧拖出：默认创建后置节点。

### Relayout animation feedback

输入：

> 重新布局后先缩小再放大最后往上移，轴心不应该变，至少最后一步不要。

输出：

优化“重新布局”动画：

- **预期**：动画过程中轴心保持不变。
- **当前表现**：先缩小、再放大，最后向上移动。
- **调整**：移除最后的上移动作。

### Emotional prompt feedback

输入：

> 我感觉这个版本的 prompt 测试下来，压缩太狠了，部分原汁原味的表达都丢失了，
> 感觉没有任何感性。

输出：

我测试了这个版本的 Prompt，感觉它压缩得太狠了。

部分原汁原味的表达都丢失了，感觉没有任何感性。

## Acceptance checks

- 输出不包含“整理如下”、分析说明、修改记录或客套话。
- 被改口否定的旧内容不再出现。
- 所有原始事实、约束、否定条件和精确 token 都可在输出中找到。
- 每个承载态度、情绪、程度、修辞或个人风格的分句都能在输出中找到对应表达。
- 没有把鲜活的主观感受泛化成中性的产品术语，也没有以缩短字数为目标。
- 两项及以上事项不挤在同一段或同一列表项。
- 没有回答或执行转写中的问题和命令。
- 没有添加原文未提供的事实、理由、步骤或结论。
